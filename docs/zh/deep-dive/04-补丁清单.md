## 一、列的口径

| 列 | 是什么 | 记住这一条就不容易读错 |
| --- | --- | --- |
| id | `lib/patches.js` 里的 `id` | **号段不连续**：1..105 缺 17 个（20 27 41 44 79 81 86 89 90 92-99），缺的号被存档区与历史删除占着，别当漏表 |
| 层 | `layer`：提示词 23 / 代码 48 / 工具 4 / 0.2.0 兼容 2 | 分层的分工见 01 第二节 |
| 名称 | `name`，代码里的常量名 | 拿它在 `lib/patches.js` 里 grep，比按 id 搜快 |
| 干什么 | `desc`，中英各一句 | 超过 70 字截断，全文在 `patches.js` |
| 目标键 | `file`（`targetFiles()` 的键） | 键能不能解析出路径取决于宿主面，见 [05-web面](05-web面.md) |
| 判据位 | 会**改变读法**的那几个字段，缩写见下 | 全字段表在 01 第三节 |
| 本机终态 | 2026-11-22 在 desktop 面跑 `patchStatusDetail()` 的结果 | **快照，不是判据**；`applied N/M` 是 `landedMarkers/declaredMarkers` |

判据位缩写：

| 缩写 | 字段 | 改了什么读法 |
| --- | --- | --- |
| `opt` | `optional: true` | 目标不在 → `na`，不是 `missing_file`（现网 36 条） |
| `strict` | `strictFiles: true` | 原文对不上 → `unmatched`（硬失败），不是 `skipped`（现网 3 条） |
| `soft` | `softSettle: true` | 布局软补丁：没有残留 pattern 就算完成，不要求 marker（现网 3 条） |
| `sat` | `satisfiedBy` | 出厂原文已达标即「没事可干」，可能一条痕迹都不写（现网 1 条：#24） |
| `mkN` | `markersWritten` N 条 | 落地率只认这 N 条；不写它时 `markers` 全算（现网 5 条 / 6 个标记） |
| `desk` | `surfaces: ["desktop"]` | 只在桌面面跑，web 面判 `na`（现网 4 条） |
| `早` | 早期形态 `patterns` + `replace` + `marker` | 没有 replacement 级 `once`，新增不许再写这种（现网 7 条） |
| `—` | 无 | 走六桶判据的默认路径 |

## 三、读这张表的四个陷阱

1. **表按 id 排过 ≠ `ALL_PATCHES` 按 id 排。** 数组顺序是按语义分段插的（会出现 73 → 71 → 5 这种跳法），这张表只是给人查才排了序。代码里按 id 取一条永远用 `ALL_PATCHES.find(p => p.id === N)`。
2. **`applied 0/0` 不是「没痕迹」。** 7 条没有声明 `markersWritten` 的补丁，落地率的分子分母都是 0；它们的 applied 来自 `markers` 命中或产物兜底（`replace` 首行前 60 字符在不在文件里）。
3. **`applied 0/1` 只有一条：#101。** 它的标记是 `[dsh-purge-101]`，而本机宿主文件里还留着旧 tag `[dsh-purge-89]`（`markers` 里为兼容留着），所以终态 applied、落地率 0/1。**要确认它真贴上，看落地率，别只看终态。**
4. **#19 在表里，但不在任何分母里。** 终态列写 `excluded`：它被 `<DSH_HOME>/dsh-purge/exclude-patches.json` 排掉了，面板那 76 条与预检那 77 条都是另起一行单列的。

## 四、重采这张表

数据只来自两处：`lib/patches.js`（结构）与 `patchStatusDetail()`（终态）。下面这段就是生成本表用的脚本（可直接跑，只读）：

```bash
cd "%USERPROFILE%/.dsh/plugins/dsh-purge"
DSH_SURFACE=desktop node --input-type=module -e '
import * as core from "./lib/core.js";
import { ALL_PATCHES } from "./lib/patches.js";
const ai = "%INSTALL_DIR%/resources/app/dsh/node_modules/@deepseek-ai";
const det = await core.patchStatusDetail(ai);
const cut = (s, n) => String(s || "").replace(/\|/g, "\\|").length > n
  ? String(s).slice(0, n).trimEnd() + "…" : String(s || "");
const rows = [...ALL_PATCHES].sort((a, b) => a.id - b.id);
for (const p of rows) {
  const f = [p.optional && "opt", p.strictFiles && "strict", p.softSettle && "soft",
             p.satisfiedBy && "sat", p.markersWritten && "mk" + p.markersWritten.length,
             p.surfaces && "desk", !p.replacements && "早"].filter(Boolean).join(" ") || "—";
  const d = det[p.id];
  const st = !d ? "excluded"
    : d.state === "applied" ? "applied" + (d.declaredMarkers ? " " + d.landedMarkers + "/" + d.declaredMarkers : "")
    : d.state;
  console.log("| " + p.id + " | " + p.layer + " | `" + p.name + "` | " + cut(p.desc, 70) + " | `" + p.file + "` | " + f + " | " + st + " |");
}
'
```

⚠ **必须带 `DSH_SURFACE=desktop`**：不带的话 8 条会从中途变成 `na`（#45 #47 #49 #57 #82 #83 #84 #91），落地率也会跟着变。理由在 [05-web面](05-web面.md)。

⚠ 这张表与 `lib/patches.js` 之间**没有门**——`assert-patches` 数的是条数和 `markersWritten` 自洽，不核这张表。所以「加了补丁忘了重生成」不会红，只会让这页慢慢过期。重生成一次不到一秒，改表后就跑。
