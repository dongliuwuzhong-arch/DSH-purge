# 03 · 备份与回滚

> 破甲自 dsh-purge 1.1.71 分出后独立维护：宿主定版在 0.2.2-rc.5，补丁表、判据与文档只服务这一棵树，不再跟随任何外部发行节奏。

这一篇只讲一件事的两面：**原件还在不在**，以及**不在的时候怎么找回来**。

补丁怎么贴不在这（00），换包怎么换在 04。

## 一、`.dshpurge.bak` 的建与拒建

打补丁前把目标文件原样拷一份，命名 `<文件>.dshpurge.bak`，放同目录。它是**唯一**能把文件退回原样的东西。

`backupAll(aiBase)` 的顺序，每一步都有理由：

| # | 情况 | 做什么 | 为什么 |
| --- | --- | --- | --- |
| 1 | 目标是用户 patch 层（`profiles/*/cordis.patch.yml`） | **永不建 bak** | 那是人的配置，不是宿主的出厂文件（#43） |
| 2 | bak 存在但 **0 字节** | 删掉重建 | 0 字节是「占位建好、内容没拷完」的残骸，通常是换包强杀留下的 |
| 3 | bak 已存在（非 0 字节） | `EEXIST`，直接跳过 | **永不覆盖** |
| 4 | bak 不存在，但目标已带本表痕迹 | **拒建**，路径进 `refused` | 拷出来的「备份」其实是打完补丁的版本 |
| 5 | bak 不存在且目标干净 | 独占占位（`wx`）+ 原子拷贝 | 正常路径 |

**为什么拒建**：`revertAll` 用「bak 与现文件字节相同」判「没被动过」。如果 bak 里装的是打过补丁的副本，回滚会直接跳过 —— 看着有备份，其实退不回来。宁可留一个明面上的缺口（`refused` 能查），也不要一份假原件。

想查这台机器的账目，**别跑 `backupAll`**：那是写操作（独占占位 + 原子拷贝，会真的建出 `.dshpurge.bak`），不是一次体检。只读的入口有两个：

```bash
cd "%USERPROFILE%/.dsh/plugins/dsh-purge"
# 1) 账目分类（只读）：missing / patched / suspect / noop 四个列表
node bin/dsh-purge.js --status | grep -A6 "备份缺口\|可疑备份\|空操作备份"
# 2) 同一份数据直连（只读）：
DSH_SURFACE=desktop node --input-type=module -e '
const c = await import("./lib/core.js");
const g = await c.backupGap("%INSTALL_DIR%/resources/app/dsh/node_modules/@deepseek-ai");
console.log({ missing: g.missing.length, patched: g.patched.length, suspect: g.suspect.length, noop: g.noop.length });
console.log(g.patched.slice(0, 5));
'
```

看到什么算对：`missing / patched / suspect / noop` 四个数加起来与 `--status` 那三行对得上；`patched` 非 0 不是故障，是「那些原件从来没被拷过」，救法在第五节。

（要真的补建备份才跑 `backupAll(aiBase)`，它的返回是 `{ made, refused, skippedUser, errors }`——`refused` 就是上表第 4 类拒绝建的那批。）

## 二、`backupGap()` 四类

它只回答「备份账目对不对」。

| 类 | 怎么判 | 含义 | 处置 |
| --- | --- | --- | --- |
| `missing` | 没有 bak | 没备份 | 看有没有 `patched` 后缀 |
| `patched` | 没有 bak + 文件有痕迹 + 这条补丁对它**不是空操作** | **原件已经没了**，得另外找 | 走第五节 2~5 |
| `suspect` | bak 在、字节与现文件相同、文件有痕迹、非空操作 | 这份「备份」是假的，回滚对它不生效 | 同上；别重复回滚 |
| `noop` | bak 与现文件相同，但补丁对该文件本来就是空操作 | **正常** | 不用管 |

面板上对应三行（`--status` 也打）：`备份缺口`（missing，带「（已带补丁痕迹：原件要另外找回）」后缀的是 patched）、`可疑备份`（suspect）、`空操作备份`（noop）。

**`noop` 与 `suspect` 长得很像，含义相反**：前者是「这条补丁对它本来什么都不做」，后者是「原件已经没了」。把这两个搞混，就会以为回滚白做了。

```bash
node scripts/check-bak-judge.mjs "%INSTALL_DIR%/resources/app/dsh/node_modules/@deepseek-ai"
```

看到什么算对：`会刷新 0` 且 `读失败 0`：

```
bak 总览 / baks: 会刷新 0 · 判为已打补丁(跳过) 49 · 备份==现网 6 · 用户 patch 层 0 · 读失败 0
```

字段逐条：`会刷新` = 下次 apply 会把 bak 刷成新原件的那几份（会另起 `would-refresh` 行逐条列出）、`判为已打补丁(跳过)` = 文件已带痕迹、`备份==现网` = bak 与现文件相同、`用户 patch 层` = 只丢 bak 不覆盖的那种、`读失败` = 读不动。只有 `会刷新` / `读失败` 非 0 时退出码才是 1。

⚠ 它**不做**上表四类的分类：这个脚本跑的是 `inspectStaleBaks`（升级预演），不是 `backupGap`。四类要看 `--status` 的三行。

## 三、`revertAll` 的十个桶

`revertAll(aiBase, options)` 把 bak 盖回去并删 bak，返回十个桶。桶名就是判据。

| 桶 | 进这个桶的条件 | 怎么读 |
| --- | --- | --- |
| `reverted` | bak 盖回去了 | 正常回滚 |
| `skipped` | bak 与现文件相同且文件无痕迹；或 `preserveClientBundles` 时被保留的前端 `client.js` | 本来就不该动 |
| `noop` | bak 与现文件相同、有痕迹，但补丁对该文件是空操作 | **正常** |
| `unrevertable` | bak 与现文件相同、有痕迹、补丁确实改过它 | **故障**：备份是假的，回滚不掉 |
| `noBackup` | 没有 bak，文件还在（且带着补丁） | 有补丁没原件；回滚**不删文件**（#41 的规矩） |
| `preservedUser` | 用户 patch 层：只丢 bak，绝不覆盖回去 | 正常 |
| `staleBak` | 调用方点名跳过的 bak（旧宿主内容，盖回去等于降级） | 防线生效了，正常 |
| `emptyBak` | bak 在但 `size <= 0` 或看起来被截断 | 全表唯一「会拿坏数据盖宿主」的地方，已被跳过 |
| `dropped` | 清掉的过期用户层 bak | 正常 |
| `errors` | 拷贝 / 删除抛错 | 逐条看，通常是文件被占用 |

回滚一次并读桶：

```bash
node --input-type=module -e '
const c = await import("./lib/core.js");
const r = await c.revertAll("%INSTALL_DIR%/resources/app/dsh/node_modules/@deepseek-ai", { preserveClientBundles: true });
for (const k of ["reverted","skipped","noop","unrevertable","noBackup","preservedUser","staleBak","emptyBak","dropped","errors"])
  console.log(k.padEnd(14), (r[k] || []).length);
'
```

看到什么算对：

- `unrevertable 0` 且 `emptyBak 0` 且 `errors 0` → 回滚干净。
- 任意一个非 0 → **停手**，先按第五节找回原件，不要连着回滚第二次（第二次只是把假原件再盖一遍）。

命令行入口等价：`node bin/dsh-purge.js --revert`（面板的「还原」同源）。

## 四、什么必须留，什么可以删

| 东西 | 位置 | 该留吗 |
| --- | --- | --- |
| `.dshpurge.bak` | 每个被打过的目标文件旁 | **必须留**。删了就等于放弃回滚 |
| asar 归档 | `<DSH_HOME>/dsh-purge/asar-archive/` | **必须留**。整树复原的唯一来源 |
| 上一版整个安装目录 | 自己拷一份 | **必须留**。官方只留最新版，旧版下不回来 |
| `~/.dsh` 冷备 | 整目录 | **必须留**。人格、配置、会话、凭据都在这 |
| 预检基线 | `scripts/preflight-baseline.json` | 必须留（进版本库）。换包后判断漂移的唯一依据 |
| 人格闸门基线 | `soul-guard.lock` | 必须留（进版本库） |
| 解包态整棵树 | `<安装目录>/resources/app` | 留着。单文件坏了不用回滚整树 |
| `desktop-install.txt` | `<DSH_HOME>/dsh-purge/` | 留着。删了破甲不知道认领哪份安装 |
| `asar-swap.json` | 同上 | **可以删**。它是换包计数台账（见 04），删了等于把「已试 3 次」清零 |
| `settle-restart.guard` | 同上 | 可以删。它是「重启节流」的时间戳，删了不会坏 |
| 旧的 `.bak-日期` 副本 | 各处 | 可以删，但先确认同目录还有 `.dshpurge.bak` |

判断标准只有一句：**能便宜重建的可以删，重建要么花钱要么没源的必须留。**

## 五、原件没了怎么救

按代价从小到大。

| 级 | 手上有 | 怎么做 | 代价 |
| --- | --- | --- | --- |
| 1 | 同目录 `.dshpurge.bak` 还能用 | 直接 `revertAll` | 零 |
| 2 | 整棵树的原件 | `<安装目录>/resources/app.asar.bak` 改名回 `app.asar`，或从 `asar-archive/` 取对应版本 | 丢所有补丁，要重贴 |
| 3 | 解封时挪走的那份 | `app.asar.dshpurge-away`（更早的命名，破甲不认这个名，但人能用） | 同上 |
| 4 | 上一版安装目录 | 拷回来覆盖 | 丢这一个版本的改动 |
| 5 | 什么都没有 | 重解包 asar：`node bin/asar-unpack.mjs <asar> <输出目录>`，7-Zip 的 asar codec 也能解 | 最贵，还要重新对齐版本 |

`unrevertable` 与 `patched` 都从第 2 级往下走。**不要重复 `revert`**。

## 六、假备份事故（1.3.3 修的 P0，一句话版）

旧实现在「判据认为文件没被打过」时会把 bak **刷新成当前文件**。判据误判一次（有补丁不落标记，比如插 import 那种），唯一一份原件就被换成打完补丁的版本。之后回滚看到 bak 与现文件相同，归进跳过：`reverted 0 / skipped N` —— 备份全在，回滚能力归零。

现在的判据：

- 刷新默认**只报告不落地**，要写必须显式传 `{ apply: true }`；
- `keys` 解析不出来时退回全表 marker 扫描，宁可少刷一份也不动既有 bak；
- 回滚输出里 `emptyBak` / `staleBak` 有值 = 防线在生效。

## 七、这台机器的账目（2026-11-22 采集）

```
备份缺口 4 个目标没有 .dshpurge.bak
  · ...\dsh-liangshen\presets\liangshen\minimal-prompt.mjs   （已带补丁痕迹：原件要另外找回）
  · ...\dsh-session-reference\lib\index.js
  · ...\dsh-session-reference\lib\types\index.js
  · ...\dsh-session-reference\lib\types\spill.js
```

读法：第一条是 `patched`（带后缀），属于「原件已经没了」；后三条是 `missing`。**`check-bak-judge` 分不清它们的 `noop` / `missing`** —— 它跑的是 `inspectStaleBaks`（升级预演），不是 `backupGap`。要分清看 `--status` 的 `空操作备份` 那一段：列在里面的路径是 `noop`（备份==现网属正常），没列进去的才是真缺。
