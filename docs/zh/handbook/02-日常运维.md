## 二、三个口径，别跨命令对数字

同一台机器、同一时刻，两条命令给出的补丁数字不同，是**正常的**。

| 口径 | 谁给的 | 事实来源 | 特点 |
| --- | --- | --- | --- |
| 明细口径 | `patchStatusDetail()`（`purge_status` 的内部值） | 逐文件判据 | 多一档 `satisfied`，最细 |
| 面板 / 字符串口径 | `patchStatus()`、`--status`、设置页 | 同上，`satisfied` 折回 `applied` | 只有五档 |
| 预检桶口径 | `preflight-upgrade.mjs` | 六桶 + 链式干跑重判 + 桌面壳单列 | 二段补丁会被改判成 `pending`；profile 提供的目标单列 |

实测同一天的对照（不是判据，是让你知道差多少）：

```
patchStatus（desktop 面）  76 条 = applied 71 / na 4 / missing_file 1
preflight（真宿主树）      77 条 = applied 76 / excluded 1（#19）
```

差在哪：预检把 `desktop-shell` 那批单独读 `lib/main.js` 判，主桶不再记 `na`；链式干跑又把「孤立判断贴不上、链上能贴」的改判成 `pending`。`patchStatus` 只读文件文本，不给链。

**规矩**：引用任何数字都带口径标签。写「applied 71（面板口径）」或「applied 76（预检桶口径）」，不写「applied 71」这种裸数。

## 三、六桶怎么读

| 桶 | 怎么判出来的 | 该紧张吗 |
| --- | --- | --- |
| `applied` | 结算了且没有非幂等的活剩下；或产物兜底成立；或明细口径的 `satisfied` 折回 | 不紧张。但要分清后面是 applied 还是 satisfied（见下） |
| `pending` | 没结算但原文还改得动；**或**结算了但还有残留 | 换包后正常；没换包就是异常 |
| `skipped` | 没结算、原文也改不动 | 分五种，非 optional 的红线 |
| `unmatched` | 带 `strictFiles` 的补丁逐字对不上 | 紧张：宿主改了这段 |
| `na` | 宿主面不同，或 `optional` 且一个目标都没解析到 | 不紧张，但**数量会随宿主版本变**，别当常量 |
| `missing_file` | 非 `optional` 且一个目标都没解析到 | 文件真缺正常；文件在却报 missing 是假漂移 |
| （`excluded`） | 不在表里，被 `exclude-patches.json` 排掉 | 不紧张，前提是四个入口都遵守 |

### 3.1 `applied` 后面有两种事实

同一句 `applied`，`patchStatusDetail()` 会分成两档：

| 明细 state | 含义 | 文件里能找到什么 |
| --- | --- | --- |
| `applied` | 我们写了痕迹，或产物兜底成立 | `[dsh-purge]` 痕迹或改写后的产物 |
| `satisfied` | 出厂原文本来就达标，**一条痕迹都没写** | 0 条本条补丁的痕迹 |

字符串口径把 `satisfied` 折回 `applied`，所以 `--status` 和面板上**看不出来**。要看明细口径：

```bash
node --input-type=module -e '
const c = await import("./lib/core.js");
const ai = "%INSTALL_DIR%/resources/app/dsh/node_modules/@deepseek-ai";
const det = await c.patchStatusDetail(ai);
const hit = Object.entries(det).filter(([, d]) => d.state === "satisfied");
console.log("satisfied:", hit.map(([id]) => id).join(",") || "无");
'
```

看到什么算对：打印 `satisfied: 无` 或只有你已知的那几条（出厂原文达标的）。有陌生的 id 就该去查是哪条补丁没落痕迹。

**痕迹账本是 `landedMarkers / declaredMarkers`，不是终态。** 现网 #24 是 `applied` 但 `landedMarkers 4 / declaredMarkers 4`；历史上曾出现过 1/4 —— 那种情况终态仍是 applied，只有落地率能看出来。

### 3.2 `skipped` 的五个来源

| 来源 | 特征 | 处置 |
| --- | --- | --- |
| ① 出厂原文已是目标形态 | `changed === false` | 正常 |
| ② optional 且目标包没装 | 与 `na` 一起看 | 正常 |
| ③ 锚点漂移，补丁彻底失效 | 非 optional，原文里 pattern 一处都没有 | 重锚（改表），别换包 |
| ④ marker 与补丁体字面不一致 | 文件里有 `dsh-purge`，终态却 `skipped` | 改 marker |
| ⑤ 二段补丁 | 干净树上必 skipped，链上能贴 | 正常，见 04 |

③ 与 ⑤ 在 `--status` 上长得一样，区别办法只有预检的「链上可贴」段。

## 四、什么时候该做什么

| 我改了什么 | 必须跑 | 可以跳过 |
| --- | --- | --- |
| 只改文档 | `assert-patches`（它核 CHANGELOG 的条数声明）、`assert-docs` | 其余全跳 |
| 改补丁表 | `assert-patches` → `assert-soul-guard` → 全量测试 → `sync-runtime --apply` → 现网树预检 → 候选树预检 | —— |
| 改 `lib/core.js` 判据 | 全量测试 → 现网树预检（仍 0 漂移）→ `check-bak-judge` | 文档那套 |
| 改 profile YAML | `check-paths` + `count-injections.mjs` + `tool_gate({action:"status"})` | 表相关的 |
| 换宿主包之后 | 04 的「换包后 30 分钟验收」八条 | —— |
| 日常开工（没改任何东西） | `check-paths` + `--status` | 其余 |
| 怀疑补丁没生效 | `check-paths` 第一条 → `--status` → 预检 | 先不要改表 |

「改了东西就跑全套」没必要；但**换包之后必须跑全套**，因为换包改的是三份数据面里的第三份（宿主树），另外两份不会跟着变。

## 五、三条红线

**红线一：非 optional 补丁从 `applied` 掉成 `skipped`。**

```bash
node scripts/preflight-upgrade.mjs --host "%INSTALL_DIR%/resources/app"
```

看到什么算对：末行「相对基线无漂移」。
出现 `⚠ 相对基线漂移 …: #NN` → 宿主改了你依赖的文本。处置：改表的 pattern / marker，**不要换包、不要回滚**。

**红线二：`applied` 但文件里找不到破甲痕迹（假绿）。**

```bash
f="%INSTALL_DIR%/resources/app/dsh/node_modules/@deepseek-ai/dsh-agent-instructions/lib/index.js"
grep -c "dsh-purge" "$f"
```

看到什么算对：非 0。
0 就是假绿——marker 取自宿主出厂原句，判定「已贴」但一个字都没写。这类靠 `markerLooksUpstream()` 挡（只认带 `dsh-purge` 字样的 marker）；新出现同类要补 marker。
⚠ 这条只在**文件级**痕迹为 0 时报警。带多目标文件的补丁要按补丁级核（`landedMarkers` 那个数）。

**红线三：备份账目里 `patched` 或 `suspect` 非空。**

```bash
node scripts/check-bak-judge.mjs "%INSTALL_DIR%/resources/app/dsh/node_modules/@deepseek-ai"
```

`patched` = 没备份而文件已带痕迹 → 原件找不回来了；`suspect` = bak 与现文件相同却带着痕迹 → 这份备份是假的。处置在 03。

## 六、定时自查项

不是定时任务，是「这几件事一周至少过一遍」。机器没开就没有对象，不是坏了。

**每次开工（30 秒）**

1. `node "%WORKSPACE%/tools/check-paths.mjs"` —— 第一行是不是解包目录。
2. `node bin/dsh-purge.js --status` —— `待清洗` 是不是 0。

**每周一次（2 分钟）**

3. `node scripts/sync-runtime.mjs` —— 源和副本一致吗（不一致 = 宿主在跑旧代码）。
4. `node scripts/check-bak-judge.mjs "<宿主插件根>"` —— `patched` / `suspect` 是否为 0。
5. `node "%WORKSPACE%\专项任务\破甲/bin/count-injections.mjs" 5` —— 每场 `重复= 0`。

**每次换宿主包前后（10 分钟）**

6. 换前：`preflight-upgrade` 退出码 0 + 留回滚资产（04 的清单）。
7. 换后：04 的八条验收 + 四道门。

**每季度一次**

8. `node --test test/*.test.mjs` 全量 + `assert-docs` —— 确认没人在你看不见的地方改坏东西。
