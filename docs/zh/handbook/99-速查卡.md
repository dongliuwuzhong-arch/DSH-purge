## Runbook 一：换一次宿主包

```
0. 留资产：asar 归档 / 上一版整目录 / ~/.dsh 冷备 / preflight-baseline.json
1. 插件先升到最新（旧插件的锚点不认识新宿主）
2. 解包候选树到任意目录（别动正在跑的安装）
3. 预检候选树 → 退出码必须是 0
4. 预检现网树 → 仍「相对基线无漂移」（这次才看得见差分）
5. 宿主正常退出（tasklist 里没有 DeepSeek）
6. 面板点「应用」让它换包；失败就看 04 第四节，别自己写脚本
7. 重启后跑 04 的八条验收
8. 四道门跑一遍
```

每步的判据：3、4 都退 0；5 无输出；7 八条各自「看到什么算对」；8 前三道绿。

## Runbook 二：回滚

```
1. node -e 'revertAll(aiBase, {preserveClientBundles:true})' 读十桶
2. unrevertable / emptyBak / errors 全 0 → 干净收工
3. 任一非 0 → 停手，按 03 第五节把原件找回（1→5 级，从便宜到贵）
4. 回滚之后重启宿主，跑四道门确认没把人格层带坏
5. 备份账目再看一次：check-bak-judge
```

十条命令见 03 第三节（可直接复制）。

## Runbook 三：这台机器从零装一遍

```
1. 装宿主，正常退出一次（让它把 resources 铺好）
2. node scripts/install-offline.mjs --source . --desktop-install "%INSTALL_DIR%"
3. 启动宿主 → 设置页点「应用」（首次会解开 asar 并自动重启）
4. 重启后再点一次「应用」（这时补丁才落在解包树上）
5. node "%WORKSPACE%/tools/check-paths.mjs" → 第一行解包目录
6. node bin/dsh-purge.js --status → 待清洗 0
7. 三处 preset maxBytes 统一 65536；全局 agent-instructions 保持 disabled: true
8. node "%WORKSPACE%\专项任务\破甲/bin/count-injections.mjs" 3 → 注入 1 份
9. 四道门
```

## 禁做清单

| 别做 | 为什么 |
| --- | --- |
| 自己写换包脚本 | 两套抢活就是 2026-11-16 那场事故 |
| 在树里没痕迹时换包 | 等于加载一份没打补丁的目录（`needs-apply-first`） |
| 连着回滚两次 | 第二次只是把假原件再盖一遍 |
| 为了让断言变绿去改断言 | 闸门一松，以后没人守 |
| 删 `.dshpurge.bak` | 那是唯一的原件 |
| 删 `asar-archive` | 那是整树复原的唯一来源 |
| 手工改宿主文件 | 下次应用会按表覆盖，改动静默消失 |
| 把 `maxBytes` 调大来掩盖截断 | 撞线推后，总量没变 |
| 照 profile 注释把全局行打开 | 注释是旧的，值才是真的 |
| 拿历史会话的 `重复` 数当现状 | 判据只看新会话 |

## 三条最短的证伪路径

遇到任何「应该是这样」的说法，先用这三条里的一条把它验掉：

```bash
node "%WORKSPACE%/tools/check-paths.mjs"                # 树对不对
node bin/dsh-purge.js --status                         # 补丁状态对不对
node scripts/preflight-upgrade.mjs --host "%INSTALL_DIR%/resources/app"   # 锚点还对不对
```

三条都过，问题就不在破甲的判据里；那时该看的是宿主和人格两条线（05 / 06）。
