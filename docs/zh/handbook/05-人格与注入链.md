# 05 · 人格与注入链

> 破甲自 dsh-purge 1.1.71 分出后独立维护：宿主定版在 0.2.2-rc.5，补丁表、判据与文档只服务这一棵树，不再跟随任何外部发行节奏。

这一篇回答四个问题：注入从哪来、为什么只能有一份、`maxBytes` 撞线会怎样、改了人格怎么验。

配置层其余部分（覆盖块、剪枝、`tool_gate`）在 01 的坑表与 06。

## 一、注入链，五段

```
① 源文件   <DSH_HOME>/plugins/dsh-purge/lib/default-prompt-inject.md     （9,461 B）
     │  scripts/embed-default-prompt.mjs（构建期把正文嵌进 lib/core.js 的密封槽）
     v
② 密封槽   lib/asset-table.js 里的一段常量 + lib/core.js 里的默认注入常量
     │  首次运行：把槽写进用户副本
     v
③ 用户副本 <DSH_HOME>/prompt-inject.md                                   （运行期读它）
     │  补丁 #1 / #2 / #3 / #101 把它挂到系统提示的指定位置
     v
④ 宿主侧   dsh-agent-instructions/lib/index.js（挂载点）
     │  三处 preset 的 agent-instructions 行（minimal / ptc / standard）
     v
⑤ 上下文   模型真正读到的 agent-instructions（每 turn 一份，见第三节）
```

每段的真源与判据：

| 段 | 真源 | 判据 |
| --- | --- | --- |
| ① | `lib/default-prompt-inject.md` | 改它**必须**重跑 `npm run embed-prompt`，否则等于没改 |
| ② | `lib/core.js` 里的默认注入常量 | `assert-soul-guard` 的「注入源 / 槽」两个指纹 |
| ③ | `<DSH_HOME>/prompt-inject.md` | `override-state.json` 里 `customized` 与 `hash` |
| ④ | profile 的 `cordis.patch.yml` | `grep -n "id: agent-instructions"` |
| ⑤ | 会话日志 | `count-injections.mjs` 数份数 |

**插件不覆盖手改过的副本。** 判定在 `override-state.json`：`customized: true` 时你的稿优先，插件不再往里写。本机现在是 `customized: false`，`hash` 与 `seedHash` 相同 —— 说明副本还是插件写的那份。

## 二、单实例怎么保证

三件事同时成立，才会只有一份。

| 前提 | 判据 | 不满足会怎样 |
| --- | --- | --- |
| 顶层全局那条 `agent-instructions` 是 `disabled: true` | profile 里 `grep -n -A2 "id: agent-instructions"` 的最后一段 | 与 preset 三处并存 → 两份实例 |
| 三处 preset 的 `maxBytes` **同值** | `grep -n "maxBytes"`，应是 `65536 / 65536 / 65536` | 值不同 → 两个实例产出的 payload 不同 → 去重失效 |
| 去重补丁在位 | `--status` 里 #105 = `applied` | 缺它就没有第二道保险 |

去重按**内容相等**判（`sameContextPayload`）：它认「同一段文本」，不认「同一个插件、不同参数」。所以 `maxBytes` 一不同，两份就都留下。

判据命令（份数）：

```bash
node "%WORKSPACE%\专项任务\破甲/bin/count-injections.mjs" 5
```

看到什么算对：每行 `注入= 1`、`重复= 0`，`budget` 只有一个值 `{65536}`。
出现 `budget={65536,98304}` 或 `重复` 非 0 → 有第二份实例或参数不一致，往下看第三节。

## 三、`maxBytes` 与截断

`maxBytes` 是宿主 `agent-instructions` 那一段的字节上限。超了就从**尾部**切。

本机（2026-11-22 实测）：

| 位置 | 值 | 状态 |
| --- | --- | --- |
| preset-minimal / preset-ptc / preset-standard 各一行 | `65536` | 生效（每会话一个实例） |
| 顶层全局行 | `disabled: true`，**没有** `maxBytes` | 关着 |
| 该全局行上方的注释 | 写着「三处均 98304」 | **谎**，以 grep 出来的值为准 |

余量怎么算：

```
<DSH_HOME>/AGENTS.md        54,622 B   ← 人格主体
工作区 AGENTS.md             4,046 B   ← 随工作区进上下文的那份
单份余量   65,536 − 54,622 = 10,914 B ≈ 10.9 KB
两份合算   65,536 − 58,668 =  6,868 B ≈  6.9 KB
```

看到什么算对：

```bash
wc -c "%USERPROFILE%/.dsh/AGENTS.md" "%WORKSPACE%/AGENTS.md"
```

两条数字加起来仍低于 65,536 就是安全区。到线之后不是「报错」，是**静默截断**：人格末尾整段消失，而界面一切正常。

截断的现场长这样（`count-injections` 输出里的 `截断×8`）：同一个会话里有 8 个 turn 的注入被切过。截断本身不报错，只有这个计数能看出来。

## 四、改了人格怎么验

五步，一步都不能省。

```bash
# 1) 改源文件（不是改 <DSH_HOME>/AGENTS.md，那是产物）
#    源在 %WORKSPACE%\knowledge\persona\
# 2) 重跑构建：必须用系统 PowerShell 5.1，脚本要 UTF-8 BOM
"C:/Windows/System32/WindowsPowerShell/v1.0/powershell.exe" -NoProfile -File "%WORKSPACE%/tools/build-agents-md.ps1"
# 3) 体积与余量
wc -c "%USERPROFILE%/.dsh/AGENTS.md"
# 4) 人格层没被动（动了就 --update 并在 CHANGELOG 写理由）
node scripts/assert-soul-guard.mjs
# 5) 重启宿主，让新会话说一句话，再数份数
node "%WORKSPACE%\专项任务\破甲/bin/count-injections.mjs" 3
```

看到什么算对：3 的体积在余量内；4 `soul-guard ok`；5 新会话 `注入= 1`、`重复= 0`，且人格里能读到刚改的那句。

⚠ 两个静默坑：

- **BOM**：`build-agents-md.ps1` 必须是 UTF-8 **带 BOM**，且用系统 PowerShell 5.1 跑。用编辑器改过脚本后 BOM 会丢，5.1 按 ANSI 读中文会报**语法错**（`Unexpected token`），那不是脚本坏了。
- **注入段被剥**：`<DSH_HOME>/dsh-purge/workspace-policy.json` 必须是 `{"policy":"always"}`。这条值错了，人格整节被剥掉而且**不报错**。

```bash
cat "%USERPROFILE%/.dsh/dsh-purge/workspace-policy.json"
```

看到什么算对：`{"policy":"always"}`。

## 五、这一篇的四个坑

| 坑 | 判据 | 处置 |
| --- | --- | --- |
| profile 注释说 98304，实值是 65536 | `grep -n "maxBytes"` | 以值为准；别照注释把全局行打开 |
| 把全局行从 `disabled` 翻成 `false` | 出现两份实例、`budget` 两个值 | 翻回去；那份注释本身就是 1.4.4 遗留 |
| 只改 `prompt-inject.md` 不改源 | 重装 / 重写槽之后改动消失 | 改源 + 重跑 `embed-default-prompt` |
| 把 `maxBytes` 调大来解决截断 | 撞线更晚，但总量没变 | 先瘦身；调大是掩盖 |

## 六、现状与一个历史现场

**现状（2026-11-22）**

| 项 | 值 |
| --- | --- |
| 三处 preset `maxBytes` | 65536 / 65536 / 65536 |
| 全局行 | `disabled: true`，无 `maxBytes` |
| 注入正文指纹 | 注入源与槽都是 `f94ed4efaf15`，闸门 digest `a889ae52cd2e` |
| 人格体积 | 54,622 B + 4,046 B |
| 用户副本 | `customized: false`，与种子同源 |
| 最近三场会话 | `注入= 1 / 重复= 0 / budget={65536}` |

**一个历史现场**（不是现在的故障，但你会在这台机器上看到它）：

```
session-cbc9338-…  minimal  user  steps=2591 turns=751  注入=1164  重复=1099  budget={65536,98304} 截断×8   ← 重复
session-7ed49e3b-…  minimal  user  steps= 904 turns= 47  注入=  17  重复=   1  budget={65536,98304}           ← 重复
```

读法：这两场的 `budget` 同时出现两个值，说明那段时间**双实例并存且参数不同**，去重失效 → 同一 turn 里两份人格，且有一份被截断。

现在这两场已经过去，判据是**新会话**：新开一场，`budget` 只有一个值、`重复= 0`，就说明没有复发。
