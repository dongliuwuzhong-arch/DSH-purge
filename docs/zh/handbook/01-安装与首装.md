# 01 · 安装与首装

> 破甲自 dsh-purge 1.1.71 分出后独立维护：宿主定版在 0.2.2-rc.5，补丁表、判据与文档只服务这一棵树，不再跟随任何外部发行节奏。

这一篇管三种「把破甲变成可用状态」的路径：**安装包**、**离线源码**、**换宿主后重贴**。

第三种最常用——换一次宿主包，补丁就全丢一次，那不是重装插件，是重贴。

---

## 零、先认清三个位置

装之前先确认这三个位置，后面每条命令都指它们。

| 名字 | 本机实际值 | 说明 |
| --- | --- | --- |
| 插件源 | `%USERPROFILE%/.dsh/plugins/dsh-purge` | 改代码改这里 |
| DSH_HOME | `%USERPROFILE%/.dsh` | profile、会话、凭据、台账都在这 |
| 宿主安装目录 | `%INSTALL_DIR%`（树在 `resources/app`） | 补丁落点 |

判据（三条都要有输出才算认清）：

```bash
node -p "require('%USERPROFILE%/.dsh/plugins/dsh-purge/package.json').version"
echo %DSH_HOME%
type %USERPROFILE%\.dsh\dsh-purge\desktop-install.txt
```

看到什么算对：第一条打印 `1.5.0`（或当前版本）；第二条 `%USERPROFILE%\.dsh`；第三条 `%INSTALL_DIR%`。

第三条是**破甲认领哪一份安装**的凭据。它写错，后面所有「应用」都会打到别的树上。

---

## 一、装法 A：安装包（zip）

包里是打包后的插件（`lib / bin / scripts / docs` 一套），不带 node_modules。

```bash
cd "%USERPROFILE%/.dsh/plugins/dsh-purge"
node scripts/install-offline.mjs --zip "<包.zip>" --desktop-install "%INSTALL_DIR%"
```

它会做五件事：解压包 → 拷到 `<DSH_HOME>/plugins/dsh-purge` → 在 profile 的 `node_modules` 建 junction → 改 profile 的 `package.json`（依赖 + `dsh.profile.bundles`）→ 写 `desktop-install.txt`。

它**不做**两件事：不打补丁、不重启宿主（脚本末行会自己说）。

看到什么算对：

```
[dsh-purge-install] installed dsh-purge@1.5.0
[dsh-purge-install] plugin:  %USERPROFILE%\.dsh\plugins\dsh-purge
[dsh-purge-install] profile: %USERPROFILE%\.dsh\profiles\desktop
[dsh-purge-install] node_modules link: created | already | replaced
[dsh-purge-install] not running pnpm; not applying patches; restart DSH then click Apply
```

只有最后一行出现，才算装对。退出码 0。

---

## 二、装法 B：离线源码（本机常用）

不打包，直接让安装器指向源码目录。

```bash
cd "%USERPROFILE%/.dsh/plugins/dsh-purge"
node scripts/install-offline.mjs --source "%USERPROFILE%/.dsh/plugins/dsh-purge" --desktop-install "%INSTALL_DIR%"
```

`--source` 省略时就取脚本所在的仓库根，所以在本仓库里裸跑等价于「把这份装进去」。

先看它要干什么（不落盘）：

```bash
node scripts/install-offline.mjs --source . --desktop-install "%INSTALL_DIR%" --dry-run
```

看到什么算对：四行 `[dry-run]` 打出来，`source` / `target` / `profile` 三条路径都对，且**没有**任何写入。

### 沙箱护栏（唯一能毁现网的开关）

不传 `--desktop-install` 时它会自己探测桌面安装目录，探测结果**往往就是现网正在用的那份**。所以默认行为是拒绝：

```
[dsh-purge-install] 装在沙箱里：加 --desktop-install <那份安装的目录>；确实要认领现网：加 --allow-live。
```

看到这一行、退出码 1，不是坏了，是护栏在拦。三条出路：

| 我想干什么 | 加什么 |
| --- | --- |
| 认领现网那份安装（本机常态） | `--desktop-install "%INSTALL_DIR%"` |
| 明确认领现网（等价，语义更直白） | `--allow-live` |
| 装到别处做实验 | `--desktop-install <那棵树>`，且 `DSH_HOME` 一起隔离 |

⚠ 第三条：只隔离安装目录、不隔离 `DSH_HOME`，影子会写现网数据。

### 一个会被踩的小坑

`node_modules/dsh-purge` 如果已经是**实体目录**（不是 junction），安装器会报：

```
... is a real directory; rerun with --force to replace it
```

处置：加 `--force`。它会把旧目录改名成 `.bak` 时间戳再建 junction，不会直接删。

## 三、装法 C：换宿主后重贴

换宿主包 / 重装宿主之后，插件还在、profile 还在，但**宿主树是全新的**——补丁一条都没了。

这一步不装插件，只重贴。

三条入口，等价：

| 入口 | 怎么做 |
| --- | --- |
| 设置页 | 点「应用」；桌面端首次会顺带解开 asar 并自动重启 |
| 宿主会话内 | 调 `purge_apply` |
| 命令行 | `node bin/dsh-purge.js --apply`（提示词 + 代码 + shim + override 一起） |

顺序要求（换包的完整流程在 04，这里只说重贴这一段）：

1. 宿主正常退出（不是硬杀，见 04）。
2. 面板点「应用」。
3. 等它自己重启，或手动重启宿主。
4. 跑下面的「装完必跑」。

看到什么算对：`purge_apply` 返回里 `applied` 数量为正、`errors` 空；重启后 `--status` 的「已清洗 / 待清洗」里待清洗为 0。

---

## 四、装完必跑

装（或重贴）完，按这个顺序跑，每一条都有输出才叫验过。

```bash
# 1. 运行副本是不是宿主真加载的那份、和源一致吗
node scripts/sync-runtime.mjs

# 2. 逐条终态（面板同源）
node bin/dsh-purge.js --status

# 3. 四道门里的三道（表 / 魂 / 版本）
node scripts/assert-patches.mjs
node scripts/assert-soul-guard.mjs
node scripts/assert-versions.mjs

# 4. 宿主树站哪边、三处落点有没有痕迹、人格几份
node "%WORKSPACE%/tools/check-paths.mjs"

# 5. 相对基线有没有漂移（换过包才需要）
node scripts/preflight-upgrade.mjs --host "%INSTALL_DIR%/resources/app"
```

看到什么算对，逐条：

| 步 | 通过形态 |
| --- | --- |
| 1 | 「已同步」或「版本一致」；不一致就 `--apply` 再重启 |
| 2 | `补丁 N/M 已清洗`、`0 待清洗`；备份缺口里没有「已带补丁痕迹」后缀 |
| 3 | `✓ 补丁表自检通过` / `soul-guard ok` / `✓ 四处一致` |
| 4 | 第一行「宿主读的是解包目录」；人格探针 1/1 |
| 5 | `破甲基准: 0.2.2-rc.5 ✓ 一致` + `相对基线无漂移`，退出码 0 |

第 4 步的脚本不在本仓库，在 `%WORKSPACE%/tools/check-paths.mjs`（随工作区走）。它退出码非 0 时**逐行看**：
- 「源与副本不一致」→ 回第 1 步；
- 「三层版本错位」→ 换包没换全，去 04；
- 第一行说读 `app.asar` → 树还没解包，去 04。

## 五、卸装

```bash
node scripts/install-offline.mjs --verify                    # 只核对装得对不对
node scripts/install-offline.mjs --uninstall                 # 卸插件（不动宿主里的补丁）
```

⚠ `--uninstall` **不是回滚**。它删插件目录与 junction；宿主里的补丁还在。
要连宿主一起还原：先在面板点「还原」，再 `--uninstall`。要连插件目录一起删，加 `--purge`。

看到什么算对：`--verify` 退出码 0 且列出 plugin / profile / link 三行；`--uninstall` 之后 `node_modules/dsh-purge` 不再存在。

---

## 六、这一篇的坑，一句话一条

| 坑 | 判据 | 处置 |
| --- | --- | --- |
| 装完没重启 | 面板看不到新补丁 id | 重启宿主（插件在装配期加载） |
| 实体副本忘了同步 | 树检查说「源与副本大小不同」 | `node scripts/sync-runtime.mjs --apply` 后重启 |
| 只有 junction 才算开发态 | junction 改源码立刻生效 | 实体副本必须 `--sync` |
| 装到沙箱却写现网 | 装了之后现网出现补丁痕迹 | 刚开始就该隔离 `DSH_HOME` |
| 装完立刻去换包 | 树里还没痕迹就换包 | 先应用再换包，见 04 的 `NEEDS_APPLY_FIRST` |
| 认领错安装 | `desktop-install.txt` 不是 `%INSTALL_DIR%` | 重装一次并带上正确 `--desktop-install` |

最后一条最隐蔽：认领错了，`--status` 会显示「未定位到当前宿主的 @deepseek-ai@」，而模板文件都还是原样。
