# 04 · 宿主换包与解包态

> 破甲自 dsh-purge 1.1.71 分出后独立维护：宿主定版在 0.2.2-rc.5，补丁表、判据与文档只服务这一棵树，不再跟随任何外部发行节奏。

这一篇管两件事：**宿主到底在读哪棵树**，以及**换一次包该怎么走、什么时候该停手**。

装插件在 01，备份资产细目在 03，出事按症状查在 06。

---

## 一、解包态是什么

宿主默认从 `<安装目录>/resources/app.asar` 读代码——只读档案，改不动。
破甲把 asar 改名（脚本里写死 `app.asar.bak`），宿主回落到 `<安装目录>/resources/app` 目录。这个目录态就是「解包态」。

**不解包，一切补丁都在空转**：文件改了，宿主读的还是 asar 里那份。

### 四条判据

```bash
# 1) asar 还在不在（列 resources 目录）
ls "%INSTALL_DIR%/resources"

# 2) 解包树在不在（**这一层只有三项**，别按 dsh / lib / node_modules 判）
ls "%INSTALL_DIR%/resources/app/dsh"

# 3) 宿主的结论（这一条最权威）
node "%WORKSPACE%/tools/check-paths.mjs"

# 4) 解包的是哪一个 asar
cat "%USERPROFILE%/.dsh/dsh-purge/unpacked-asar.json"
ls -l "%USERPROFILE%/.dsh/dsh-purge/asar-archive"   # 目录，看文件名与大小
```

看到什么算对：

| 判据 | 通过形态 | 不通过说明 |
| --- | --- | --- |
| 1 | 列出里**没有** `app.asar`，有 `app/` 目录 | 还有 asar = 密封态，补丁全空转 |
| 2 | `resources/app/dsh` 里只有 `desktop-runtime.json` / `node_modules` / `package.json` **三项**，且 `node_modules/@deepseek-ai` 下能列出 300 多个 `dsh-*` 目录（本机 327 个）；`dsh` / `lib` / `renderer` / `runtime` 在**上一层** `resources/app` | 这一层连 `node_modules` 都没有 = 解包没做或做坏了。⚠ 按「`dsh` / `lib` / `node_modules` 都在」判会把健康的树判成坏的——1.5 之前的文档就是这么写的 |
| 3 | 第一行「宿主读的是解包目录：…\resources\app（依据：进程命令行 --app-path）」 | 说读 `app.asar` = 树站错了 |
| 4 | `unpacked-asar.json` 的 size 等于归档里某一份 | 对不上 = 解包的是别的包 |

⚠ 一个反直觉的坑：**`app.asar` 在某些安装包里是目录不是文件**。那时命令行带 `--app-path=...\app.asar`，`existsSync` 全是 false，看起来「没有 asar」其实还是密封的。判据 3 能识破它。

## 二、换包的三条路

| 谁动手 | 什么时候 | 怎么做 |
| --- | --- | --- |
| 面板 / 工具 | 手上有人 | 点「应用」；桌面端首次会顺带解开 asar 并自动重启；宿主会话里是 `purge_apply` |
| 启动自愈 | 没人看着，asar 又回来了 | 宿主启动时自己判、自己换，见第三节 |
| 手工兜底 | 上面两条都没成 | 杀干净 → 改名 → 重启，见第六节 |

**别自己写换包脚本。** 破甲自己有（`lib/desktop.js` 里的 `ASAR_SWAP_PS1`）。两套抢活就是 2026-11-16 那场事故。

那段 PowerShell 按顺序做六件事（记住它，才知道失败时停在哪一步）：

1. 只按**本次安装根路径**枚举进程并结束（不用 `/IM` 全名杀，避免误伤同名程序）。
2. 再等 500ms 再杀一次，再等 300ms —— 让 UI 来不及画出「host stopped」对话框。
3. 10 秒兜底循环：本进程和同安装根的进程都不在了才往下。
4. `app.asar.unpacked` 在而关键 `.node` 不在 → `robocopy` 把 `app` 目录补回来。
5. `Move-Item app.asar → app.asar.bak`，失败重试 80 次（每 400ms；第 20 / 50 次再杀一轮），并写 `.rename-pending` 锁标记。
6. 重启宿主。

看到什么算对：第 5 步成功后 `.rename-pending` 消失、`resources` 里出现 `app` 且没有 `app.asar`；第 6 步之后宿主能开，且 `check-paths` 第一行说读解包目录。

## 三、启动自愈的七档状态机

宿主每次启动都会判一次「现在该干什么」。判定函数是 `decideHealAction()`（`lib/sealed-heal.js`），七档：

| 档 | 触发条件 | 含义 | 它会做什么 |
| --- | --- | --- | --- |
| `healthy` | asar 不在，树有痕迹 | 一切正常 | 什么都不做 |
| `needs-reapply` | asar 在，树有痕迹 | 官方更新 / 手动重装把 asar 换回来了 | 重打补丁 + 换包 + 重启 |
| `needs-unbury-bak` | asar 不在，但 `app.asar.bak` 还躺在 `resources` 里 | 下次官方更新会把 bak 复原成 asar | 只把 bak 挪走 |
| `needs-apply-first` | 树在但**一条痕迹都没有** | 换了包还没打补丁 | **不换包**，等点「应用」（换了等于加载未打补丁的目录） |
| `broken-no-tree` | 补丁树都不在 | 无法自愈 | 等点「应用」重新解包 |
| `needs-manual-apply` | 同一份 asar **已换 3 次都没成功** | 结构性失败（权限 / 杀软 / 跨盘） | **停手**，不再杀进程 |
| `needs-asar-rename` | `<asar>.rename-pending` 存在 | 上次改名失败，通常是占用 | 只试一次改名，成功就不杀进程 |

三条要记住的规矩：

1. **上限是 3**（`HEAL_SWAP_ATTEMPT_LIMIT`）。计数只在「同一个 asar 身份」下延续：asar 的 size 或 mtime 一变，说明官方真换了新包，计数归零。
2. **台账是 `<DSH_HOME>/dsh-purge/asar-swap.json`**：`attempts` / `lastError` / `at` / 那份 asar 的 `size + mtime`。成功或被清空就消失。
3. **`needs-apply-first` 是保护**，不是故障：树里没痕迹时换包，会把一份没打补丁的目录推上去。

日志在 `%LOCALAPPDATA%\Temp\dsh-purge-desktop.log`，只追加、超 2MB 翻滚成 `.1`：

```bash
grep -n "heal:" "$LOCALAPPDATA/Temp/dsh-purge-desktop.log"
```

看到什么算对：正常运行时没有 `heal:` 行，或只有 `heal:unburied-bak` 这种一行的收尾。
出现 `heal:reapply-failed` / `heal:swap-schedule-failed` / `heal:unbury-failed` = 那一步没成，按下一节处置。

## 四、`NEEDS_REAPPLY` / 失败怎么处置

先看台账，再看日志，最后才动手。

```bash
cat "%USERPROFILE%/.dsh/dsh-purge/asar-swap.json"    # 没有这个文件 = 没失败记录
grep -n "heal:" "$LOCALAPPDATA/Temp/dsh-purge-desktop.log"
tasklist | findstr /I "DeepSeek"                          # 宿主还活着吗
```

| 现象 | 一眼判据 | 处置 | 看到什么算对 |
| --- | --- | --- | --- |
| 每次启动都在杀进程重启 | `asar-swap.json` 的 `attempts` 一直加 | 清掉台账（删 `asar-swap.json` 或面板点「应用」走成功路径），然后手工换一次包 | 台账不再增长，`check-paths` 第一行是解包目录 |
| `needs-manual-apply` | `attempts >= 3` | 停手。查权限 / 杀软 / 跨盘，再手工兜底 | 手工改名成功、宿主能起 |
| `needs-asar-rename` | `resources` 里有 `app.asar.rename-pending` | 宿主完全退出后手工改名（见第六节），再删 `.rename-pending` | `.rename-pending` 消失 |
| `needs-apply-first` | 树在，`grep -c "dsh-purge"` 目标文件是 0 | 先点「应用」打补丁，**别换包** | 痕迹非 0 之后再换 |
| `needs-unbury-bak` | `resources` 里同时有 `app` 与 `app.asar.bak` | 把 bak 挪到 `asar-archive/`（或直接删） | `resources` 里只剩 `app` |
| `broken-no-tree` | `resources/app/dsh` 不在 | 重新解包（面板应用会做），或从归档 asar 重来 | 树回来、痕迹回来 |

**别做的三件事**：

- 不要在台账还在涨的时候连着硬杀 —— 那是「重启一次被杀一次」的循环本体。
- 不要在树里没痕迹时换包。
- 不要手工把 `app.asar.bak` 改回 `app.asar` 又指望补丁还在（那是回滚，不是换包）。

## 五、防「反复被杀」的五条

1. **正常退出，不是硬杀。** 运行时改名必然 `EBUSY`，硬杀也不行（子进程还握着句柄）。托盘也关掉。
2. **让破甲自己换。** 它的脚本会等进程干净、会重试、会写锁标记；你自己的脚本不会。
3. **别把尝试次数喂满。** 每次启动自愈失败都会 +1；三次之后它停手，你只能手工。所以第一次失败就该停下来看日志。
4. **重启节流要留着。** `<DSH_HOME>/dsh-purge/settle-restart.guard` 是「最近一次重启」的时间戳，窗口内不再重启（`shouldSkipSettleRestart()`，默认 180 秒）。删了它不会坏，但会把节流一并清掉。
5. **台账与锁标记是给人看的。** `asar-swap.json`（次数 + 上次错误）、`.rename-pending`（改名没完成）。两个都在的时候，先处理锁，再清计数。

## 六、换包三步

### 第 0 步：留资产

换包前必须有的四样（清单在第八节）：`app.asar.bak` 或 `asar-archive` 里的归档、上一版整个安装目录、`~/.dsh` 冷备、`preflight-baseline.json`。

### 第 1 步：停宿主

```bash
tasklist | findstr /I "DeepSeek"
```

看到什么算对：**没有输出**。有输出就等它退干净（正常退出，不要 `taskkill /F`）。

### 第 2 步：让它换

优先级：面板「应用」→ `purge_apply` → 等启动自愈 → 手工。

手工兜底（自动化失败时）：

```bash
# 1) 确认没有宿主进程
tasklist | findstr /I "DeepSeek"
# 2) 改名（路径按本机）
mv "%INSTALL_DIR%/resources/app.asar" "%INSTALL_DIR%/resources/app.asar.bak"
# 3) 重启宿主 → 它回落到 resources\app
# 4) 换完第一件事不是看功能，是看树
node "%WORKSPACE%/tools/check-paths.mjs"
```

看到什么算对：第 4 步第一行「宿主读的是解包目录」。

## 七、换包后 30 分钟验收（八条）

```bash
# 1) 树
node "%WORKSPACE%/tools/check-paths.mjs"
# 2) 逐条状态（CLI 自己定档，第二行应是 surface desktop）
node bin/dsh-purge.js --status
# 3) 备份账目
node scripts/check-bak-judge.mjs "%INSTALL_DIR%/resources/app/dsh/node_modules/@deepseek-ai"
# 4) 破甲自己写的两个宿主侧文件在不在（换包后必须回写）
ls "%INSTALL_DIR%/resources/app/dsh/lib/dsh-purge-child-process-hide.mjs" \
   "%INSTALL_DIR%/resources/app/dsh/lib/dsh-purge-hide-console.js"
# 5) 人格份数
node "%WORKSPACE%\专项任务\破甲/bin/count-injections.mjs" 5
# 6) 剪枝
node "%WORKSPACE%/tools/check-pruner.mjs"
# 7) 预设仍是合法 YAML
python -c "import sys,yaml; yaml.compose(open(sys.argv[1],encoding='utf-8')); print('ok')" \
  "%INSTALL_DIR%/resources/app/dsh/node_modules/@deepseek-ai/dsh-web-app/presets/minimal.patch.yml"
# 8) 相对基线无漂移（同样必须带 surface）
DSH_SURFACE=desktop node scripts/preflight-upgrade.mjs --host "%INSTALL_DIR%/resources/app"
```

看到什么算对：1 第一行「宿主读的是解包目录」（末行是「全部验过」或「有 1 处对不上：三层版本错位」——后者是底座旧，常态）；2 `补丁 N/M 已清洗, 0 待清洗`；3 `会刷新 0` 且 `读失败 0`，以及 `--status` 的备份缺口行没有「（已带补丁痕迹：原件要另外找回）」后缀；4 两个文件都在；5 每场 `重复= 0`；6 「原始实现在线」+ 四处 32768；7 打印 `ok`；8 退出码 0 且「相对基线无漂移」。

⚠ 第 8 步必须带 `DSH_SURFACE=desktop`（预检自己不定档，不带会报 3 条假漂移 #47 #49 #57）；第 2 步不用——`--status` 会自己按安装锚点定档。

功能面只验四个，别铺开：**ptc 档能跑 `run_code`**、**新会话说一句话人格 1 份**、**设置页能开**、**退出不弹窗**（下一节的例外）。

## 八、回滚资产清单

| 资产 | 位置 / 名字 | 谁认它 |
| --- | --- | --- |
| asar 原件 | `<安装目录>\resources\app.asar.bak` | **破甲认这个名字**；`.manual-swap-*` 这类它看不见 |
| asar 归档 | `<DSH_HOME>\dsh-purge\asar-archive\` | 破甲自己归档；换包后整树复原的唯一来源 |
| 解封时挪走的那份 | `app.asar.dshpurge-away` | 只有人认，救急用 |
| 上一版整个安装目录 | 自己拷一份 | 官方只留最新版，旧版下不回来 |
| `~/.dsh` 冷备 | 整目录 | 人格、配置、会话、凭据全在里面 |
| 预检基线 | `scripts/preflight-baseline.json` | 判断「漂移」的唯一依据 |
| 人格基线 | `soul-guard.lock` | 判断注入层有没有被顺手改 |
| 解包态整棵树 | `<安装目录>\resources\app` | 单文件坏了不用回滚整树 |

本机现状（2026-11-22）：`asar-archive` 里有两份官方 asar —— `app.asar.rc3-official-20261121-191935.bak`（209,021,953 B）与 `app.asar.rc5-official-20261121.bak`（209,083,008 B）；`unpacked-asar.json` 记的 size 是 209,083,008，说明当前解包的是 rc.5 那份。

## 九、窗口期弹窗：已知，不算回归

现象：换包后第一次退出宿主，弹一次「… quit unexpectedly」。

原因：抑制这个对话框的是补丁 #83 / #84，它们改的是**解包后的** `lib/main.js`；而换包那一刻 Electron 读的还是官方 `app.asar`，补丁没在这次启动里生效。

所以：

- 升级窗口期弹一次 = 已知，**不算回归**，不用处置。
- 非换包时刻也弹 = 真回归，去查 #83 / #84 的终态与 `lib/main.js` 里的 `dsh-purge` 痕迹。

根除要改整个换包流程（先解包打补丁再启动），风险和收益不成比例，明确不做。
