## §1 补丁全落空，面板还显示已打

- **判据**：`node "%WORKSPACE%/tools/check-paths.mjs"` 第一行；或看进程命令行里有没有 `--app-path=...\app.asar`。
- **病因**：宿主从 `app.asar`（只读档案）读代码，`resources/app` 里的改动没人用。
- **处置**：宿主正常退出 → 让破甲换包（或手工把 `app.asar` 改名 `app.asar.bak`）→ 重启 → 重看第一行 → 重贴补丁（01 的装法 C）。
- **变体**：`app.asar` 可能是**目录**，命令行带 `--app-path`，于是 `existsSync` 全 false。这条也是「影子树不能叫 `*.asar`」的原因。
- **看到什么算对**：第一行「宿主读的是解包目录」，且目标文件里 `grep -c "dsh-purge"` 非 0。

## §2 面板绿了但行为没变（假绿）

- **判据**：`applied` 但文件里 0 条痕迹。

```bash
f="%INSTALL_DIR%/resources/app/dsh/node_modules/@deepseek-ai/dsh-agent-instructions/lib/index.js"
grep -c "dsh-purge" "$f"
```

- **病因**：marker 取了宿主出厂原句（不带 `dsh-purge` 字样），于是「判定已贴」而一个字没写。`markerLooksUpstream()` 就是挡这个的。
- **处置**：给该条补上带 `dsh-purge` 的 marker，重跑 `assert-soul-guard --update`（写理由）+ 预检。
- **多目标补丁的例外**：文件级 grep 会骗你。带多个目标文件的补丁要看 `patchStatusDetail()[id].landedMarkers` 与 `declaredMarkers` 两个数（02 的 3.1）。

## §3 宿主起不来 / 一开就退

按顺序排三件事。

1. **预设 YAML 是否合法**（最像：轮廓对了，缩进错一格）

```bash
python -c "import sys,yaml; yaml.compose(open(sys.argv[1],encoding='utf-8')); print('ok')" \
  "%USERPROFILE%/.dsh/profiles/desktop/cordis.patch.yml"
```

看到什么算对：打印 `ok`。红的话先把 `cordis.patch.yml.<日期>.bak` 拷回来（改配置前应当先备份）。

> 为什么用 `yaml.compose` 而不是 `yaml.safe_load`：预设里有 `!!js` 标签，PyYAML 造不出对象会直接 ConstructorError；`compose` 只解析结构，缩进错才红。

2. **覆盖块有没有把插件整段吃掉**：`grep -n "tool-executor-ptc\|tool-office"`。ptc 档缺 `tool-executor-ptc` 时那一档没有 `run_code`（不崩，但整张工具表回到固定开销）。
3. **运行副本是否损坏**：`node scripts/sync-runtime.mjs`，不一致就 `--apply`。

三条都过还起不来 → 看日志最后 20 行：

```bash
powershell -NoProfile -Command "Get-Content \"$env:LOCALAPPDATA\Temp\dsh-purge-desktop.log\" -Tail 20"
```

- **看到什么算对**：日志里没有连续重复的 `heal:` 行。有就是在换包循环里，去 04 第四节。

## §4 换包后弹一次崩溃窗

- **判据**：只在那一次换包之后第一次退出时出现，之后不再。
- **病因**：换包那一刻 Electron 读的是官方 `app.asar`，抑制弹窗的 #83 / #84 没在这次启动里生效。
- **处置**：不用处置。若非换包时刻也弹 → 查 `lib/main.js` 里 `dsh-purge` 痕迹与 #83 / #84 终态。
- **看到什么算对**：第二次、第三次退出都不再弹。

## §5 人格少了一段

- **判据**：`wc -c` 撞线。

```bash
wc -c "%USERPROFILE%/.dsh/AGENTS.md" "%WORKSPACE%/AGENTS.md"
findstr /C:"截断" "%LOCALAPPDATA%\Temp\dsh-purge-desktop.log"
```

- **病因**：`maxBytes` 到线后从尾部切，静默。
- **处置**：瘦身（减冗余段），不是调大 `maxBytes`。
- **看到什么算对**：两份体积之和回到 65,536 以下，且新一轮 `count-injections` 里没有 `截断` 标记。

## §6 人格两份（重复注入）

- **判据**：`count-injections` 里 `budget` 出现两个值，或 `重复` 非 0。
- **病因**：顶层全局 `agent-instructions` 行被打开，与 preset 三处并存；或三处 `maxBytes` 不同。
- **处置**：全局行 `disabled: true`；三处 `maxBytes` 同值；重启后重数。
- **看到什么算对**：新会话 `budget={65536}`、`重复= 0`。
- **注意**：历史会话里的 `重复` 不会消失（它是当时的现场），判据只看**新会话**。

## §7 `EBUSY` / `EPERM` / 拒绝访问

- **判据**：`tasklist | findstr /I "DeepSeek"` 还有进程；或报错里带 `rename` / `.tmp`。
- **病因**：宿主握着文件句柄。写盘层有退避重试（20 / 60 / 150ms），仍失败会抛「宿主进程可能正占用该文件，退出 DeepSeek Harness 后重试」——**看到这句话就是没退干净**，不是补丁坏了。
- **处置**：正常退出（不是 `/F` 硬杀，托盘也关）；确认 `tasklist` 空；重跑。杀软锁文件同理，必要时把安装目录加进排除。
- **看到什么算对**：`tasklist` 空输出，命令不再报错。

---

## §8 web 面打不开 / 端口不对

- **判据**：你敲的地址打不开，而运行时上下文里给的是另一个端口。
- **事实**：桌面端没有端口概念；web 面的端口由宿主给（`PORT`，默认 3080），而且**每次重启都可能不同**。所以地址永远从运行时上下文/会话信息取，别记死。
- **处置**：先取当前地址；仍不通就看端口是否被占：

```bash
netstat -ano | findstr :<端口>
```

- **看到什么算对**：`netstat` 里那个端口处于 `LISTENING`，浏览器能开。
- **另一个坑**：宿主是单实例应用，重复点开会静默退出（不报错）。看起来「打不开」，其实是已经在跑。

## §9 运行副本落后（宿主跑的是旧代码）

- **判据**：`node scripts/sync-runtime.mjs` 说源与副本不一致；或 `--status` 里「运行副本 … 与源码差 N 个文件」。

```bash
node scripts/sync-runtime.mjs
node scripts/sync-runtime.mjs --apply
```

- **病因**：运行副本是**实体副本**（不是 junction），改源之后没同步。宿主加载的永远是副本。
- **处置**：`--apply` → 重启宿主。
- **看到什么算对**：「全部同步」，且 `check-paths` 里「源与副本一致」那几行都是 `[✓]`。

## §10 剪枝自检红

- **判据**：`node "%WORKSPACE%/tools/check-pruner.mjs"` 说「代码层: 禁用态(#19)」或阈值显示死配置。
- **病因**：#19 被贴上了，`pruneContent()` 变成 `return null`，四处阈值一起变死配置。
- **处置**（四步，别走「从 bak 还原 + 手改预设」那条老路，下次应用会把 #19 贴回去）：

```bash
printf '{"excludePatches":[19]}' > "%USERPROFILE%/.dsh/dsh-purge/exclude-patches.json"
cp "%INSTALL_DIR%/resources/app/dsh/node_modules/@deepseek-ai/dsh-compaction-tool-result-pruner/lib/index.js.dshpurge.bak" \
   "%INSTALL_DIR%/resources/app/dsh/node_modules/@deepseek-ai/dsh-compaction-tool-result-pruner/lib/index.js"
# 重启宿主
node "%WORKSPACE%/tools/check-pruner.mjs"
```

- **看到什么算对**：「代码层: 原始实现在线」+ 四处都是 32768。

## §11 预检退 2 / 退 1

| 码 | 含义 | 你要做什么 |
| --- | --- | --- |
| 0 | 没有非可选失配，也没有相对基线的漂移 | 可以换包 |
| 2 | 有非可选失配（含桌面壳）；或有基线时出现漂移；加 `--strict-missing` 时 `missing` 也算 | **先修锚点，别换包** |
| 1 | 用法 / 环境错：`--host` 指不到 `@deepseek-ai` | `--host` 要 `...\resources\app`（不是 `resources`） |

退 2 时逐条判：

- **二段补丁**（锚点由前一条插入）→ 不是故障，应在「链上可贴」那段里；不在那段才去查它的前置。
- **`desktop-profile` 区的 `missing`**（贴点在 profile 里的那几条）→ 异树假漂移，换包不动它们。
- **真失配** → 改 `lib/patches.js` 的 pattern / marker，重跑到 0 再换包。

绝对不要「先换包再说」：贴不上的补丁会在新宿主上留下半截行为，比不贴更难查。

```bash
node scripts/preflight-upgrade.mjs --host "%INSTALL_DIR%/resources/app" --json
```

- **看到什么算对**：`--json` 里 `chainRescued` 覆盖了疑似二段的那几条，且漂移集合为空。

## §12 测试数字 / 文档断言对不上

- **判据**：`node scripts/assert-docs.mjs` 红，且红项落在你没改的文件里。
- **处置**：先分清三件事——(1) 是真过期数字，改文；(2) 是别人负责的文件，记录在案并交给那一篇的作者；(3) 是你新写的文件，改文。
- **不要**为了让它变绿去放宽断言。断言变松，等于这条路以后没人守。
- **看到什么算对**：`六类全绿`；若红在别处，至少你负责的文件不再出现在红项列表里。

---

## §13 状态数字互相矛盾

- **判据**：两个命令给出不同的 applied 数。
- **病因**：三个口径（面板 / 预检桶 / 明细），见 02 第二节。
- **处置**：给数字标口径；需要绝对值时重新跑命令，别抄三个月前的。
- **看到什么算对**：你能说出「这个数来自哪条命令、哪个口径」。

---

## §14 `dsh` 命令不存在 / shim 三件 missing

- **判据**：`--status` 末尾 `shim: dsh.cmd=missing dsh.ps1=missing dsh=missing`；或 shell 里敲 `dsh` 提示找不到。
- **事实**：shim 是「顺手装」的那一层，管的是命令行短名与隐藏 cmd 闪窗，**不影响补丁与人格**。
- **处置**：要用短名再装；不装就永远写全路径 `node bin/dsh-purge.js …`。
- **看到什么算对**：`--status` 那三行不再是 `missing`；或你根本不依赖短名。

---

## 结尾：三条别做

1. **别在没预检的情况下换包。**
2. **别为了让断言变绿去改断言。**
3. **别拿「没有输出」当「已经做了」。** 说「已经修好了」之前，先有一条命令的输出摆在那儿。
