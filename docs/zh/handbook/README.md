# 破甲运维手册

> 破甲自 dsh-purge 1.1.71 分出后独立维护：宿主定版在 0.2.2-rc.5，补丁表、判据与文档只服务这一棵树，不再跟随任何外部发行节奏。

读者只有一个：三个月后的我，手里只有这台机器。

所以这一册不写原理推导，只写「先看什么、再敲什么、看到什么算对」。

## 这一册管什么

- 装、验、日常看、备份、回滚、换宿主包、人格注入、出事怎么查。
- 全部判据都给出**命令 + 通过的形态**。形态会随版本变，命令不会。
- 数字只在一处出现（`02-日常运维.md` 的「现状快照」），其余各篇写口径不写绝对值。

不管什么：补丁表逐条改了什么（`../deep-dive/01-补丁表.md`）、判据为什么这么算（`../deep-dive/02-判据与状态机.md`）、某条结论当年怎么查出来的（`../history/`）。

## 三条入口命令

三条命令都从插件仓库根跑（`<DSH_HOME>/plugins/dsh-purge`）。

```bash
node scripts/assert-patches.mjs      # 表自洽吗（条数 / id 唯一 / 与 CHANGELOG 声明一致）
node scripts/assert-soul-guard.mjs   # 人格注入与 14 条关键补丁没被顺手改
node bin/dsh-purge.js --status     # 逐条终态、备份账目、运行副本（自己按安装锚点定档）
```

看到什么算对：

- 第一条末行 `✓ 补丁表自检通过`，退出码 0。
- 第二条 `soul-guard ok` 且 digest 与 `soul-guard.lock` 里的一致。
- 第三条第二行应是 `surface desktop（判据 / via: 安装锚点）`，并打出 `补丁 N/M 已清洗`、`0 待清洗`、备份缺口里没有「已带补丁痕迹」后缀的行。若它显示 `surface web` + 「插件根未找到」，说明安装锚点没写，加 `--surface desktop` 应急（理由见 02 §一）。

## 数字的口径

同一台机器上，补丁状态有三个口径，数字不同是正常的，别互相校对。

| 口径 | 谁给的 | 特点 |
| --- | --- | --- |
| 明细口径 | `patchStatusDetail()`（`purge_status` 的内部值） | 多一档 `satisfied`，最细 |
| 面板 / 字符串口径 | `patchStatus()`、`--status`、设置页 | `satisfied` 折回 `applied`，五档 |
| 预检桶口径 | `preflight-upgrade.mjs` 的六桶 + 链式干跑重判 | 会把二段补丁改判成 `pending`、桌面壳单列一段 |

引用任何数字都要带口径标签。不带标签的数字，三个月后就是一条查不动的账。
